# alperna.ch One-Pager Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Einen vertrauenswürdigen One-Pager für alperna.ch bauen, mit Hero-Buttons «Termin buchen» und «Gratis Marketing-Check», auf GitHub und Vercel.

**Architecture:** Next.js App Router, eine Startseite aus Abschnittskomponenten, Inhalte zentral in `lib/`. Der Marketing-Check ist eine Client-Zustandsmaschine (Formular → Analyse läuft + E-Mail-Popup → Ergebnis), die Analyse läuft über eine Proxy-Route zur bestehenden Engine in `alperna-tool`.

**Tech Stack:** Next.js 16, React 19, TypeScript 5.9, reines CSS, zod, Vitest (Unit), Playwright (E2E), sharp (Bilder).

**Spec:** `docs/superpowers/specs/2026-10-05-onepager-design.md`

## Global Constraints

- Anrede **Du** auf der ganzen Seite. Schweizer Schreibweise: `ss` statt `ß`, Tausender mit `’`, Guillemets «…», `CHF 1’000`.
- Alle Fakten kommen aus `lib/site.ts`: 28 Partner, seit 3 Jahren, ca. 25’000 Beiträge, Preise ab CHF 1’000 (Website), ca. CHF 2’000 (mit Shooting), ab CHF 180 (Beitrag). Keine abweichende Zahl im Seitentext.
- Gold `#FFD700` nie als Fläche und nie als Textfarbe auf hellem Grund. Fliesstext 19 px (mobil 18 px), Buttons mindestens 52 px hoch.
- Keine Tracking-Skripte, keine Cookies. Calendly lädt erst beim Öffnen des Dialogs.
- Seite bleibt `noindex`, solange `NEXT_PUBLIC_INDEXABLE` nicht `1` ist.
- Keine Secrets im Repo. `N8N_WEBHOOK_URL` und `CHECK_API_URL` nur als Umgebungsvariablen.
- alperna.ch (Framer) wird nicht angefasst.

### Task 4: API-Routen

**Files:** `lib/schemas.ts`, `lib/ratelimit.ts`, `app/api/check/route.ts`, `app/api/lead/route.ts`, `app/api/kontakt/route.ts`, Tests `tests/unit/ratelimit.test.ts`, `tests/unit/api.test.ts`

**Interfaces:**
- Produces:
  - `zuOft(key: string, max: number, fensterMs: number): boolean`
  - `checkSchema` (Eingabe: `company, city?, industry (Enum), website, socials?`), `leadSchema` (`email, einwilligung: true, company, website, branche?, ort?, score?: number, befunde?: string[], status: 'ergebnis'|'fehler'`), `kontaktSchema` (wie `websitev2`)
  - `POST /api/check` → `200 {ok:true, ergebnis: CheckErgebnis}` | `400 {ok:false,grund:'ungueltig'}` | `429 {ok:false,grund:'zu_oft'}` | `502 {ok:false,grund:'analyse'}`
  - `POST /api/lead` → `200 {ok:true}` | `400` | `503 {grund:'nicht_konfiguriert'}` | `502`. Sendet an `N8N_WEBHOOK_URL` ein Objekt `{name:'Marketing-Check', firma, email, themen:['Marketing-Check'], nachricht, quelle:'alperna.ch/marketing-check', zeit}`
  - `POST /api/kontakt` → wie `websitev2`, Honigtopf liefert `200` ohne Versand

- [ ] Tests zuerst (`fetch` global gestubbt): `zuOft` liefert beim 6. Aufruf mit `max=5` true und nach Ablauf des Fensters wieder false. `/api/check`: ungültige URL → 400, 5 gültige Aufrufe passieren und der 6. liefert 429 (gleiche IP), Upstream-Fehler → 502, Upstream ohne `score` → 502, Erfolg → `ok:true` mit durchgereichtem Ergebnis. `/api/lead`: ohne Einwilligung → 400, ohne `N8N_WEBHOOK_URL` → 503, gültig → `fetch` wird einmal mit `email` im Body aufgerufen. `/api/kontakt`: gefüllter Honigtopf → 200 und `fetch` nicht aufgerufen
- [ ] Implementieren (Quelle: `websitev2/app/api`), Tests grün
- [ ] Commit

### Task 5: Marketing-Check

**Files:** `lib/check.ts`, `components/MarketingCheck.tsx`, `components/CheckErgebnis.tsx`, Tests `tests/unit/check.test.ts`, `tests/e2e/check.spec.ts`

**Interfaces:**
- Consumes: `POST /api/check`, `POST /api/lead`, `useTermin()`
- Produces: `type CheckErgebnis`, `type CheckKategorie`, `naechsterBaustein(e): {slug; titel; kategorie} | null`, Phasen `'form' | 'popup' | 'ergebnis'`

- [ ] Unit-Test `naechsterBaustein`: grösste gewichtete Lücke gewinnt; `null` bei Lücke < 2; Google Ads nur, wenn alle anderen Kategorien ≥ 0.6
- [ ] E2E-Tests mit gemockten Routen (`page.route`), jeder zuerst rot:
  1. Pflichtfelder fehlen → Fehlermeldung, kein Popup, kein Request
  2. Gültig + «Check generieren» → Popup sichtbar, `/api/check` wird sofort gesendet
  3. Popup ohne E-Mail abschicken → Fehlermeldung, Ergebnis bleibt verborgen, auch wenn die Analyse fertig ist
  4. E-Mail + Checkbox → Ergebnis mit Gesamtnote sichtbar, `/api/lead` genau einmal mit `email` und `score`
  5. Popup schliessen ohne E-Mail → Formularwerte bleiben erhalten, kein `/api/lead`
  6. `/api/check` liefert 502 → Fehlermeldung mit Kontakt-Hinweis, E-Mail wird als Lead mit `status:'fehler'` gesendet
- [ ] Umsetzen: Analyse sofort starten (`AbortController`), Popup mit Fortschrittsliste, Ergebnis erst wenn `emailOk && analyse` vorliegen, Lead einmalig senden
- [ ] Commit
